# Database design

PostgreSQL (embedded 18 for dev/tests; managed PostgreSQL 16+ in production). UUIDv7 keys generated by the application. All timestamps UTC (database timezone pinned by migration). Every clinic-owned table has `tenantId` + RLS. Source of truth: `prisma/schema.prisma` + `prisma/migrations/`.

| Platform | `PlatformUser`, `PlatformSession`, `PlatformInvitation` |
| Tenancy | `Tenant`, `Branch`, `Department`, `Plan`, `Subscription`, `TenantModule` |
| Identity & access | `User`, `Session`, `Membership`, `MembershipBranch`, `Role`, `RolePermission`, `MembershipRole`, `Invitation` |
| Support | `SupportAccessGrant` |
| Audit | `AuditEvent` — append-only, per-tenant SHA-256 hash chain |
| Auth (Phase 4) | `PasswordReset` (hash-only, single-use) |

| Laboratory (Phase 8a) | `LabAnalyte` (per lab-test service: name, UCUM-style unit, reference range CHECK low ≤ high, optional LOINC), `LabOrder` (number CHECK `LAB-YYYY-NNNNNN`, status ORDERED → COLLECTED → RESULTED → VERIFIED / CANCELLED, priority, who/when for each step; four-eyes CHECK `verifiedById <> resultedById`; trigger forbids deletion and any change after VERIFIED/CANCELLED), `LabOrderItem` (test name snapshot), `LabResult` (Decimal value, unit and range snapshot, flag; unique per item+analyte; trigger blocks writes once the order is final). Grants to `itopmed_app` only |
| Patient portal (Phase 8b) | `PatientAccount` (one per patient per clinic; login phone unique per clinic with CHECK on format; argon2id hash; INVITED/ACTIVE/DISABLED with CHECK that ACTIVE has login + password; activation code hash + expiry; lockout counters), `PatientSession` (hash-only). `LabOrder.releasedAt/releasedById` (one-way release, CHECK verified-only; the lab order trigger permits only this change on verified orders). Functions: `portal_current_account/patient/tenant()` (identity from the session hash), `portal_auth_lookup`, `portal_auth_record_failure`, `portal_activation_lookup`, `portal_activate` (atomic, re-checks code/expiry/lock/birth date), `portal_doctor_names`. Third runtime role `itopmed_portal` with column-level grants and `portal_*` policies |
| Pharmacy & inventory (Phase 8c) | `InventoryItem` (code CHECK, category, form/strength, unit, reorder level), `Supplier`, `StockBatch` (per branch: lot, expiry, cost; `quantity` CHECK ≥ 0, forced to 0 on insert, **no UPDATE grant** — maintained only by the ledger trigger), `StockMovement` (append-only ledger; sign / patient / reason CHECKs; `stock_movement_apply` SECURITY DEFINER trigger locks the batch, refuses expired issue/dispense and applies the quantity; update/delete blocked even for the owner). Dispensing rows reference the patient, so no platform grants |
| HR (Phase 8c) | `StaffProfile` (minimal: personnel no. unique per clinic, position, department, employment type, hire date, work phone), `StaffCredential` (licences/certificates, expiry, archive), `StaffLeave` (category only, range CHECK ≤ 365 days, APPROVED/CANCELLED). `ScheduleException.leaveId` links a doctor's days off to the leave that created them |
| Resources & scheduling (Phase 5) | `Room`, `Service` (price in BigInt minor units + currency), `DoctorProfile`, `DoctorService`, `WorkSchedule` (ISO weekday + local minutes, CHECKs), `ScheduleException` (category only, no free text) |

SQL objects: `app_current_tenant/user/session/invite_token_hash()`, `app_auth_lookup_user()` and `app_auth_record_failure()` (SECURITY DEFINER, EXECUTE revoked from PUBLIC), `audit_event_chain` trigger, `audit_verify_chain()`, immutability triggers, CHECK constraints (locales, slug format, lowercase emails, support-grant duration and reason). Databases are created UTF-8 (`C` collation).

## Planned clinical and operational schema (Phases 5–8)
Structured data, not free text. Each table: `tenantId`, RLS, grants to `itopmed_app` only, audit on clinical read/write.

| Module | Tables |
|---|---|
| Patients | `Patient` (split names, birthDate, sex, status, mergedIntoId), `PatientIdentifier` (PINFL / passport / insurance / MRN; unique per tenant+type), `PatientContact`, `PatientConsent` (purpose, legalBasis, granted/withdrawn), `DuplicateCandidate` (score, review status) |
| Scheduling | `Service`, `ServicePrice` (validity periods), `Room`, `DoctorProfile`, `WorkSchedule`, `ScheduleException`, `Appointment` + exclusion constraint (`tstzrange`, `btree_gist`) preventing practitioner/room overlaps, `QueueTicket` |
| EMR | `Encounter`, `ClinicalNote` (template, structured sections, draft/signed, signer, content hash), `ClinicalNoteAmendment` (append-only with reason), `Diagnosis` (ICD-10), `AllergyIntolerance`, `Observation`/vitals (LOINC + UCUM), `MedicationStatement`, `Prescription`, `CarePlan`, `FollowUp` |
| Lab & diagnostics | `LabOrder`, `LabOrderItem`, `Specimen`, `LabResult` (value, unit, reference range, flags, verifier), `DiagnosticReport`, `ImagingStudy` |
| Documents | `Document` (storage key, sha256, mime, classification), `DocumentAccessLog`, `Template` |
| Finance | `Invoice`, `InvoiceLine`, `Payment` (method, provider ref, idempotency key), `Refund`, `CashShift`, `CashMovement`, `LedgerEntry`; money as `BigInt` minor units + currency |
| Inventory (remaining) | `PurchaseOrder`, transfers between branches, prescription-linked dispensing |
| HR (remaining) | `Shift`/timesheets, `StaffDocument` (needs protected document storage) |
| Notifications | `NotificationTemplate` (per locale), `Notification` (no PHI payload), `OutboxMessage` |
| Integrations | `IntegrationConfig` (encrypted credentials), `IntegrationEvent` (direction, idempotency key, status, attempts, payload hash) |

## Rules
* Clinical writes and their audit event share one transaction.
* Signed notes are immutable (trigger); corrections are amendments with who/when/why.
* Clinical data is archived, not deleted; hard deletion only through a documented retention process.
* Coding: ICD-10 (ICD-11 path), LOINC, UCUM; mapping to FHIR R4 for DMED exchange.
* Indexes lead with `tenantId`; trigram index for patient-name search.
