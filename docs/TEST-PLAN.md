### Phase 8a lab walkthrough (2026-11-11)

The integration test DB now runs with `io_method=sync` because PostgreSQL 18 I/O workers could outlive an interrupted run on Windows and block port 54339.

### Phase 9 accessibility audit (2026-11-13)
axe-core 4.14 (WCAG 2.1 A + AA rules) run in the real browser on the dev build, signed in as every role: public pages (clinic sign-in, password reset, portal sign-in/activation), receptionist (dashboard, patients, patient, queue, booking), doctor (medical record, visit with dental chart, today's queue), lab (worklist, order, tests), pharmacist (stock, item), HR (list, person), doctor schedule, cashier (billing, invoice, receipt, cash desk), patient portal (home, appointments, result, payments, account), owner (settings, setup, integrations, roles, team, audit, reports) — in dark and light mode. Found and fixed: white text on the bright accent (3.29:1) on every primary button → solid fill tokens; accent badges in dark mode (4.15:1) and several light-mode tones on grey (3.8–4.4:1) → stronger tokens; light caption grey (≈3.5:1) and dark caption on tinted cards (4.19:1); translucent bars letting content bleed under text; tables and the dental chart not keyboard-scrollable; tooth links whose accessible name lacked the visible code. Final run: 0 violations on every audited screen. Not covered by automation: real screen-reader use, cognitive load, zoom to 400 % on real devices.
